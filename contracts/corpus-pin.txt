# contracts/corpus-pin.txt — the corpus snapshots a fresh clone SEEDS from, by digest.
#
# Read by the pipeline's `seed` / `seed-etsi` steps (internal/goal/seed_pin.go):
# each arm pulls exactly the manifest named on its line, and checks the bytes the
# registry serves against that digest before transferring anything. A tag such as
# `latest` is moved by whoever publishes; a digest is the snapshot itself, so the
# corpus a clone starts from is fixed by the commit it checked out.
#
# WHO BUMPS IT: scripts/local/publish-corpus.sh, right after it pushes a snapshot
# (it rewrites only the line of the package it pushed). Commit the change in the
# same PR as whatever made the new snapshot worth publishing — until it is merged,
# a fresh clone keeps seeding the previous one. Do not edit it by hand to a digest
# nobody verified.
#
# WHAT A BUMP COSTS: `seed` / `seed-etsi` re-run and DECLINE on any machine that
# already holds a corpus (about a second each) and carry their provenance forward,
# so nothing behind them replays and no corpus byte moves. Only a machine without
# a corpus pulls the new snapshot.
#
# Overrides, for trying another snapshot without editing this file:
#   MCP3GPP_CORPUS_REF_3GPP / MCP3GPP_CORPUS_REF_ETSI  — a tag or a digest, per package
#   MCP3GPP_CORPUS_TAG                                 — one TAG for both (no digest)
#

# pinned as found. Both predate the 2026-09 corpus (the 3GPP layer is 8.1 GB
# compressed against a 23 GB 3gpp.duckdb today; the ETSI layer is 32 MB, from
# before the all-versions campaign, against a 19.5 GB etsi.duckdb): they seed a
# starting point that the rest of each arm completes. Republishing is what
# refreshes them — and what bumps these lines.
